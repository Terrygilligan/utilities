# Per-tool star rating + reviews with JSON-LD

Add a reusable ToolRating component (5 stars, local average/count, optional review) mounted once in Layout above every tool page's header, persisting to utility-hub.* localStorage and injecting Schema.org WebApplication/AggregateRating JSON-LD per route.

## Summary

Implement a per-tool rating widget across all 31 tool pages of the Utility Hub PWA. Per user's choice, it mounts once inside `Layout.tsx` at the top of `<main>` (directly above each page's h1 header), driven by the current route — uniform placement, automatic coverage for future tools, ~6 files touched instead of 31. Ratings persist locally under the `utility-hub.` prefix so they ride backups/Sync Hub for free, and each tool route injects `application/ld+json` WebApplication + AggregateRating markup into `<head>`.

**Honest caveat (noted for the owner):** with no backend, the aggregate is the rating stored on this device — `ratingCount` is 0 until the user rates, then 1. JSON-LD `aggregateRating` is only emitted once a real local rating exists (never fake zero-count markup). Google generally won't show star snippets for unverifiable ratings, so treat the markup as spec-correct plumbing rather than guaranteed SERP stars.

## Implementation Steps

### 1. `src/lib/ratings.ts` (new) — storage + schema helpers

```ts
export interface ToolRatingData { rating: number; review: string; updatedAt: string }
const key = (toolId: string) => `utility-hub.rating.${toolId}`
export function loadRating(toolId): ToolRatingData          // JSON.parse w/ fallback {rating:0, review:'', updatedAt:''}
export function saveRating(toolId, data)                    // sets updatedAt=ISO, localStorage.setItem (try/catch)
export function buildToolSchema(toolName, url, rating, count) // WebApplication object; aggregateRating only if count>0
```

Per-tool keys (vs one map) so Sync Hub merges ratings per tool instead of replacing the whole blob. The `utility-hub.` prefix means `dataKeys()` in backup.ts picks them up automatically.

### 2. `src/lib/tools.ts` (new) — extract TOOLS from Home.tsx

Move `interface Tool` + the 33-entry `TOOLS` array (route path as `id`, English `title`, icon) from `src/pages/Home.tsx` into `src/lib/tools.ts`, including the needed lucide imports. `Home.tsx` imports `{ TOOLS }`/type instead of defining them — single source of truth shared by Home and Layout. `DEFAULT_ORDER` stays in Home (derived).

### 3. `src/components/ToolRating.tsx` (new)

- Props: `{ toolId: string; toolName: string }` (toolId = route slug e.g. `pdf`, `totp`; toolName = English title for the schema `name`).
- State: `rating`/`review` loaded via `loadRating`, `hover` for star preview, `reviewOpen` toggle, brief "Saved locally" confirmation (reuses existing key).
- UI (slim card strip, mobile-first, dark-aware):
  - 5 star `<button>`s (lucide `Star`, `fill-amber-400 text-amber-400` when active), click → `saveRating` immediately; `aria-label={t('Rate {n} stars', { n })}`.
  - Readout: `{avg.toFixed(1)}` + `{count} {t(count === 1 ? 'rating' : 'ratings')}`; when count=0 show `t('Not rated yet')`; small `{t('Rate this tool')}`/`{t('Average rating')}` labels.
  - `{t('Leave a review')}` toggle → textarea (rows 2, `t('Your review (optional)…')` placeholder, prefilled) + `{t('Submit Rating')}` button → `saveRating`; `{t('Hide review')}` to collapse.
- JSON-LD `useEffect` (deps: toolId/toolName/rating): upserts `<script id="utility-hub-tool-jsonld" type="application/ld+json">` in `document.head` with `buildToolSchema(toolName, location.href, rating, count)`; cleanup removes it so each route's markup is exclusive.

### 4. `src/components/Layout.tsx` — mount the strip

- Add small wrapper inside `<main>` above `<Outlet/>`:
  ```tsx
  const tool = TOOLS.find((tool) => tool.to === pathname)
  {tool && <ToolRating key={pathname} toolId={tool.to.slice(1)} toolName={tool.title} />}
  ```
  `key={pathname}` forces a fresh mount per tool (clean state + JSON-LD swap). No match on `/` or `*` → nothing renders.
